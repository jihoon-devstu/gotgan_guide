01최종 아키텍처

계층별 구성

계층구성 요소역할
엣지Vercel · Route 53 · ACM · EIP · NLB
  • Vercel: 프론트 정적 파일 + /api/*를 API로 rewrite → 브라우저 입장 같은 출처
  • Route 53: api.gotgan.click A 레코드 → NLB 고정 IP(EIP 2개)
  • NLB: LBC가 생성, 교차 영역 분산, 443 리스너에서 ACM 인증서로 TLS 종료 → gateway 8080
게이트웨이gateway-service ×2
  • 단일 진입점, 경로 → 서비스 라우팅 (03장 · 8-3 라우팅 표)
  • Keycloak 발급 JWT를 JWKS로 검증 (Spring Security oauth2ResourceServer)
  • 클레임 → X-User-Id · X-User-Roles · X-Store-Id 헤더 주입
인증Keycloak (realm gotgan)
  • 계정(이메일 · 비밀번호) · 역할 BUYER · SELLER · ADMIN · 토큰 발급
  • ClusterIP만 — 로그인 · 가입은 우리 React 화면 → user-service가 대리 호출
업무 서비스 (백 티어)user · store · product · order · payment · review · settlement · admin — EKS app 노드(t3.xlarge ×2)
  • 기능(데이터 소유권) 기준 분할, 데이터까지 완전히 독립
  • ClusterIP — 외부 직접 접근 불가, 서비스 간 동기 호출은 /internal/**만
  • admin은 DB 없음 — 관리자 화면용 조합 계층(BFF)
데이터 (DB 티어)MySQL 1대(스키마 8) · Redis — EKS db 노드(t3.medium, 2a) + EBS 볼륨(gp3 디스크) · DynamoDB · S3
  • 서비스별 스키마 · 계정, 교차 JOIN · FK 금지
  • NetworkPolicy: 3306 · 6379는 백 티어(tier=backend) 파드만, DB 파드는 밖으로 안 나감
  • Redis: cart:{userId} · (blacklist:{jti} Could) — 캐시 · 리프레시 토큰 키 없음
  • DynamoDB: Lambda 데이터(알림 이력 · 명세서 발송 이력)
비동기SNS 토픽 3 · SQS 큐 · DLQ
  • "일어난 일" 통보 (입점 승인, 결제 완료, 구매확정, 취소 · 반품, 정산 지급)
  • 3회 실패 시 DLQ
서버리스Lambda 3 · SES · EventBridge
  • 배치 · 로깅만, 사용자 API 없음
  • 알림 메일 · 정산 명세서 · 로그 아카이브
외부포트원 V2 (테스트 채널)
  • 브라우저 결제창, payment-service가 결제 조회 · 취소 API로 검증
배포 · 운영GitHub Actions · SonarQube Cloud · ECR · ArgoCD · PLG + Zipkin
  • CI: 테스트 · 정적 분석 · 빌드 · ECR push · 태그 커밋
  • CD: ArgoCD가 Git의 Helm values를 클러스터에 동기화 → 롤링 업데이트(무중단)
  • 관측성: 지표 · 로그 · 트레이스 + Grafana "System Status" 헬스 체크 대시보드

3브라우저가 포트원 결제창으로 테스트 결제—
4POST /api/orders/{orderNo}/payment/confirm → order → payment /internal/payments/verify(포트원 조회 금액 = 기대 금액)PAID / 불일치 시 포트원 자동 취소 → 재고 해제 → 포인트 환원 → FAILED

공통 규칙

API

  • 구매자·공개: /api/{자원}
  • 판매자: /api/seller/{자원} — SELLER만
  • 관리자: /api/admin/{자원} — ADMIN만, 전부 admin-service가 받아 각 서비스 /internal/** 호출
  • 내부: /internal/{자원} — 게이트웨이 미노출
  • 자원명 복수형 · kebab-case (/order-items)

응답 · 에러

  • 모든 응답: ApiResponse<T> 봉투 { code, message, data } — 성공은 code: "SUCCESS"
  • 에러: 같은 봉투 + 의미형 code (예: ORDER_OUT_OF_STOCK), data: null
  • 페이지: ApiResponse<PageResponse<T>> — {content, page, size, totalElements, totalPages, hasNext}
  • 검증 실패 400 · 인증 401 · 권한·소유권 403 · 없음 404 · 상태 충돌 409 · 다른 서비스 응답 실패 · 타임아웃 502/504(EXTERNAL_API_ERROR)

데이터

  • PK: {테이블}_id 단일 BIGINT AUTO_INCREMENT
  • 외부 번호: 주문 20261001-000123, 상품주문 …-01
  • sagaId · eventId: UUID
  • 시간: DB · JDBC · JVM 모두 Asia/Seoul · 서비스 밖으로 나가는 이벤트 시각만 오프셋 포함 ISO-8601
  • 생성 · 수정 시각: DB가 DEFAULT · ON UPDATE로 기록, 엔티티는 @Generated로 읽기만 (JPA Auditing 사용 안 함)
  • 금액: 원 단위 long/BIGINT, 비율 BigDecimal/DECIMAL(5,2)
  • 다른 서비스 데이터: ID만 참조 + 필요한 값 스냅샷

설정 · 프로필

  • application.yml: ${환경변수:로컬기본값}만, 비밀 값 금지
  • local: IDE 실행 · 시드 데이터 · 로컬 docker-compose(MySQL · Redis · Keycloak)
  • k8s: ConfigMap이 활성화 · Loki 전송
  • 비밀 값: GitHub Secrets → secrets-sync 워크플로 → K8s Secret → 환경 변수 (로컬은 .env.local · compose 기본값)
  • 데모용 주기 단축은 환경 변수로 (AUTO_CONFIRM_AFTER=2m)

장애 격리 (Resilience4j)

  • 대상: Saga 단계 호출 · 대시보드 조합 · admin의 모든 /internal/** 호출
  • 타임아웃 연결 2s · 읽기 3s · 서킷 브레이커(서비스별 인스턴스) · 재시도는 멱등 GET만
  • 폴백: Saga는 보상 후 EXTERNAL_API_ERROR(502/504), 대시보드는 실패 영역만 null + unavailable
  • 서킷 상태는 Micrometer 지표로 Grafana에 노출

입력 보안

  • SQL Injection: JPA · QueryDSL 파라미터 바인딩, @Query · 네이티브 쿼리 문자열 이어 붙이기 금지 (SonarQube 검출)
  • XSS: 사용자 입력 HTML은 OWASP Java HTML Sanitizer로 저장 전 정화 (허용 태그 정책 1개를 공통으로)
  • 개인정보 · 토큰 · 포트원 키는 로그 금지

  • 포인트 UI: 주문서 "보유 ○○P · 사용" 입력(보유 이내 · 결제 금액 이내) + 예상 적립(실결제금액 5%) 표시 · 마이페이지 포인트 내역 · 등급 배지

  • 사유 reason: CHANGE_OF_MIND(단순변심) · DEFECTIVE(상품불량) · WRONG_DELIVERY(오배송) · ETC + 상세 사유 텍스트 — 거부는 판매자 사유 필수
  • 반품 환불액 = 그 상품주문의 실결제 배분액 − 반품 배송비(단순변심일 때만, 스토어 기본 배송비 × 2). 판매자 귀책(불량 · 오배송)은 전액
  • 교환은 같은 옵션 재배송만 · 이번 범위에서 교환 배송비는 청구하지 않음 (결제 변동 없음)
  • 한 상품주문에 진행 중 클레임은 1개 · 환불 Saga는 claimId를 멱등 키로 사용
  • 포트원 취소가 실패하면 재고 복원 · 포인트 환원을 진행하지 않고 APPROVED(또는 COLLECTED)에 머무른 채 Saga 복구 스케줄러가 재시도
